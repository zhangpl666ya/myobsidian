# Python - 网络请求 错误处理

> 生产环境的网络请求必须包 `try/except`，否则一个 500/超时就能让程序崩溃。

## 标准模板

```python
import requests

try:
    response = requests.post(url, headers=headers, json=payload, timeout=15)
    response.raise_for_status()
except requests.exceptions.HTTPError as err_http:
    print(f"HTTP 错误: {err_http}")      # 抓 401/404/500
except requests.exceptions.Timeout:
    print("请求超时")                     # 抓慢挂死
except Exception as e:
    print(f"其他错误: {e}")              # DNS/SSL/JSON 解析等
```

## 三个核心异常类

| 异常 | 触发场景 |
|---|---|
| `requests.exceptions.HTTPError` | `raise_for_status()` 发现非 2xx |
| `requests.exceptions.Timeout` | 超过 `timeout=` 设定未响应 |
| `Exception` | 其他一切（DNS/SSL/JSON 解析） |

> 🔑 三个异常类顺序：先具体后通用。`Exception` 必须放最后。

## 常见坑

- ⚠️ 不设 `timeout=` → 网络挂死时程序卡住
- ⚠️ 不调用 `raise_for_status()` → 服务器 500 你还以为成功
- ⚠️ `try/except` 顺序写反 → 具体异常被通用 `Exception` 拦截

## 自检清单

- [ ] 每个网络请求都设了 `timeout=`
- [ ] 调用了 `r.raise_for_status()` 或用 `try/except` 捕获
- [ ] `except` 顺序：具体异常在前，`Exception` 在最后
