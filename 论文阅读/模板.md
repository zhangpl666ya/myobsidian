科研阅读不是把论文读懂就结束，而是要训练自己回答：

> **作者为什么提出这个问题？怎么解决？为什么相信这个方法有效？哪里可能有漏洞？**

下面给你一个偏**AI/机器人/机器学习论文**的阅读填空模板。你可以直接复制到 Obsidian。

---

# 📄 Paper Reading Template

## 0. 基本信息（建立索引）

```
论文名称：

作者：

会议/期刊：

年份：

领域：
（CV / NLP / RL / Robotics / Embodied AI）

论文链接：

代码链接：
```

---

# 1. Abstract（摘要）怎么读

## 阅读目标：

不要试图理解细节，只回答：

> 这篇论文想解决什么大问题？

填空：

```
这篇论文研究的问题是：

过去的方法主要存在的问题是：

作者提出的方法叫：

核心思想是一句话：

作者声称取得的效果：
```

---

例如：

论文：

> RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control

填写：

```
研究问题：
如何让机器人利用大规模视觉语言模型获得更强泛化能力？

过去问题：
传统机器人策略需要大量机器人数据，泛化能力弱。

方法：
把VLM迁移到机器人控制。

一句话：
让机器人像语言模型理解文字一样理解动作。
```

---

# 2. Introduction（引言）

这是论文最重要部分。

不要急着看公式。

读 Introduction 时，画一条逻辑链：

```
现实问题
    ↓
已有方法
    ↓
已有方法为什么失败
    ↓
作者提出新方向
```

填写：

---

## 2.1 Problem（问题）

```
作者观察到的现实问题：

为什么这个问题重要：

如果解决，可以带来什么：
```

---

## 2.2 Previous Work（过去方法）

```
以前主要有哪几类方法：

方法A：
核心思想：

缺点：


方法B：
核心思想：

缺点：
```

---

## 2.3 Gap（研究空白）

这是论文灵魂。

填写：

```
以前方法不能解决的问题：

原因是什么：

作者认为突破点在哪里：
```

---

## 2.4 Contribution（贡献）

通常 Introduction 最后会列：

"We make three contributions"

不要直接复制。

翻译成自己的话：

```
贡献1：

贡献2：

贡献3：
```

判断：

```
真正创新的是：
```

---

# 3. Related Work（相关工作）

不要当历史课读。

目标：

知道作者站在哪个山头。

填写：

```
这个领域有哪些主要路线？

路线1：
代表论文：
核心思想：


路线2：
代表论文：
核心思想：


本文属于：
```

# 4. Method（方法）

这是第二遍重点阅读。

不要直接看公式。

先回答：

## 4.1 Overall Idea（整体框架）

看 Figure 1。

填写：

```
输入：

经过：

模型：

输出：

整个pipeline：
```

画：

```
Input
 ↓
?
 ↓
?
 ↓
Output
```

---

## 4.2 每个模块

每个模块重复：

```
模块名称：

作用：

为什么需要它：

输入：

输出：

核心公式：

我的理解：
```

---

例如：

Transformer Encoder

```
作用：
提取输入序列关系

为什么需要：
因为机器人动作依赖历史状态

输入：
image tokens

输出：
latent representation

我的理解：
把复杂视觉信息压缩成机器人可使用的信息。
```

---

# 5. Formula（公式）

不要问：

“这个公式怎么推导？”

先问：

## 公式三问

```
① 它描述什么？

② 每个变量是什么？

③ 为什么这样设计？
```

模板：

```
公式：

变量：

物理意义：

作者想优化：

为什么这样定义：
```

---

# 6. Experiment（实验）

很多初学者这里看结果表。

其实应该先看：

## 6.1 实验目的

填写：

```
作者想证明：

实验设计：

如果方法有效，应该看到：
```

---

## 6.2 Dataset

```
数据集：

为什么选择这个数据：

规模：

是否公开：
```

---

## 6.3 Baseline

非常重要。

填写：

```
比较对象：

为什么选它：

它代表什么水平：
```

---

## 6.4 Results

不要只写：

"提升5%"

填写：

```
主要结果：

提升最大的地方：

说明：

失败的地方：

说明：
```

---

# 7. Ablation Study（消融实验）

这是判断作者有没有骗人地方。

问：

> 去掉一个零件，会不会坏？

填写：

```
实验去掉：

结果：

说明这个模块：
```

---

例如：

```
去掉pretraining：

性能下降30%

说明：
预训练是性能来源之一。
```

---

# 8. Discussion / Limitation

很多论文藏在这里。

填写：

```
作者承认的问题：

我发现的问题：

实际部署困难：

未来方向：
```

# 9. Reviewer模式（读完以后）

假装自己是审稿人。

回答：

## 优点

```
最大的贡献：

为什么重要：
```

---

## 缺点

```
最大漏洞：

实验是否充分：

有没有隐藏假设：
```

---

## 如果我继续研究

```
我会改进：

下一篇论文可以研究：
```

# 最终一页总结（强烈建议）

读完后压缩成：

```
论文一句话：

它解决：

核心方法：

最大创新：

关键实验：

最大缺陷：

我的启发：
```

## 推荐你的实际阅读流程（AI时代）

不要从第一页线性读：

```
第一遍：
Abstract
↓
Introduction
↓
Figure 1
↓
Conclusion

目标：
知道故事


第二遍：
Method
↓
Formula
↓
Experiment

目标：
知道怎么做


第三遍：
AI辅助

问：
为什么？
有没有问题？
怎么复现？
```

---

对于你现在关注的**具身智能 / Agent / Robotics论文**，我建议额外增加三个栏目：

```
机器人状态(state):

观测(observation):

动作(action):

学习目标(loss):

数据如何采集:

部署需要什么硬件:
```

因为机器人论文和纯AI论文最大的区别是：**它最后必须落到真实世界里的动作闭环。** 🤖

这个模板可以直接作为你的 Obsidian 论文库模板。你以后每读一篇论文，就像给它做一次“科研尸检报告”。逐渐会形成自己的研究地图。
